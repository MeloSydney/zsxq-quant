# 统一市场态度打分 Rubric（-2 … +2）

适用：DGF（大锅饭）与 Duoyu（多鱼）两条知识星球流水线的共享打分阶段（③）。
产出：`reviewed.json` 数组，每条 `{post_id, score, scope, timescale, evidence}`，
由 `__common/stance.py` 做 schema 与覆盖校验。

## 1. 打分性质与 timescale

- 打分对象是**当前市场情绪**，用途是判断**未来两个交易日股市的买入/卖出**倾向，
  即短期两个交易日情绪信号；不是对帖子质量、也不是对个股长期基本面的评价。
- `timescale` 字段默认填写「未来两个交易日」；若星主明确给出其他时间窗口
  （如「下周」「年底前」），按原帖窗口填写并在 evidence 中说明。
- 五档映射到买/卖情绪强度（见 §2），独立于原帖「能量评分」。

## 2. 五档语义

| 分值 | 语义 | 典型表述 |
|---|---|---|
| **+2** | 明确看多，建议增加风险敞口 | 加仓、买入、提高仓位、明确看多 |
| **+1** | 偏多/看好修复，但提示风险 | 看好反弹但控制仓位、逢低关注 |
| **0** | 中性 / 方向信息不足 | 见下方三类理由 |
| **-1** | 偏空/谨慎，建议降低敞口 | 反弹持续性存疑、减仓观望、谨慎 |
| **-2** | 明确看跌，要求避险减仓 | 清仓、避险、明确看跌、大幅减仓 |

`0` 的 evidence **必须区分三类理由**，不得笼统写「中性」：

1. **多空相抵**：同帖（含星主后发回复）同时存在方向相反且强度相当的判断；
2. **震荡观望**：星主明确表达「观望/区间震荡/等信号」；
3. **方向信息不足**：正文与可辨认材料中星主未表达任何市场方向判断
   （如纯资讯转述、正文截断、纯提问无星主实质回答）。

## 2.1 量化判定与相邻档排除（两源一致执行）

每条非 0 分 evidence 必须完成**双向量化论证**，格式与 duoyu-pipeline 现行做法一致：

1. **取档依据**：点明命中的 §2 档位语义或典型表述（如「反弹持续性存疑/谨慎」→ -1，
   「明确看多建议加仓」→ +2），并引用正文/OCR/评论中的原文片段支撑；
2. **相邻档排除**：明确说明为何**不**记相邻档。±1 必须说明未达到 ±2 的指令强度
   （如「未对读者发出清仓/大幅减仓指令，故不记 -2」）或未弱化为 0（方向判断明确、
   非多空相抵/观望/信息不足）；±2 必须说明超过 ±1 的依据（存在明确的避险/加仓指令）。
3. `0` 分按 §2 三类理由之一写明，不允许跳过归类。

示例（duoyu 实际输出）：「条件性弱反弹且明确本周非好时点，属降低敞口倾向记 -1；
未对读者发出清仓/大幅减仓指令，故不记 -2。」DGF 与 Duoyu 逐帖 evidence 均按此格式，
确保两源使用同一量化评分算法、事后可审计打分边界。

## 3. 输入边界

只允许依据以下材料打分：

- 星主帖**正文**；
- 帖内**可辨认的图片 OCR 文本**（无法辨认的 OCR 不参与，不得猜测）；
- **明确归属于星主的回答/评论/回复**（含星主在提问帖下的实质回答）。

非星主用户的评论只能作上下文参考，不得单独作为打分依据。被 filter manifest
排除的帖子**不打分**，reviewed.json 不得包含其 post_id。

## 4. evidence 与 scope 要求

- `evidence` **必填且可追溯**：引用原文片段、OCR 内容或具体评论楼层，
  能定位到帖子内的出处；不得为空、不得是通用模板句。
- 观点针对**单一标的/板块**时，`scope` 必须注明适用范围
  （如「英伟达 CPO 产业链」）；针对大盘整体情绪时填「大盘整体」。
  一帖多标的时写最主要的判断对象并注明其余（如「大盘整体（兼及光模块）」）。

## 5. 冲突与转述处理

- **同帖冲突**：正文与评论/回复方向不一致时，以**后发的星主回复**为准；
  无法判断先后时按多空相抵记 0，并在 evidence 中说明。
- **研报/外部观点转述**：星主转述研报或他人观点时，标注「帖文引用观点」，
  不得冒充星主个人判断；仅当星主附加了自己的认可/反驳/操作建议时，
  按星主的附加态度打分，evidence 中同时注明引用部分与附加态度。
- **focus-owner 不写死**：各源自行配置 focus-owner 名单（DGF=三线文案大锅饭；
  Duoyu=求学、大牛等），rubric 与共享代码均通过参数接收，不在本文件硬编码
  校验逻辑。

## 6. 输出契约

- `score` ∈ {-2, -1, 0, 1, 2}（整数）；`scope`/`timescale`/`evidence` 均为非空字符串。
- 覆盖守恒：reviewed.json 恰好覆盖全部 **kept** 帖，每帖一条，不重不漏
  （由 `__common/stance.validate` 与 `__common/validate.py` 校验）。
