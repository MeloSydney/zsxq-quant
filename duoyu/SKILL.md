# 多鱼朋友圈完整流程

目标星球：`https://wx.zsxq.com/group/15284854485542`。只操作本仓库 `duoyu/`，不要调用大锅饭脚本或读取 `/Users/melo/doc-Dgf/zsxq_md/`。

1. 按北京时间确定日期。无参数为今天及之前两天；`Nd` 为最近 N 个自然日；单日或 `start:end` 为闭区间。

3. 脚本从 API 分页抓取并审计全部帖子，下载附图并以 macOS Vision OCR 提取真实文字，图片和 OCR 均嵌入自包含 HTML。检查来源、日期、逐日数、API 分页返回数 = 范围外 + 重复 + 范围内数，且默认 `#host-posts` + `#questions` 的卡片数等于范围内数。检查 11-11 17:53 求学的纯图片帖子及“至少这周没打脸”帖的原图和 OCR 内容；无法辨认的图片不能编造文字。
4. raw 路径 `/Users/melo/doc-Dgf/duoyu/{MMDD}-多鱼朋友圈_raw_{start}_{end}.html`。按下方“多鱼朋友圈原文分析”章节逐张阅读 raw 卡片的正文、OCR、回答和有价值评论，写 `/Users/melo/doc-Dgf/duoyu/{MMDD}-多鱼朋友圈_{start}_{end}.md`。不要将 OCR 自动当成准确事实：与内嵌原图核对含糊数字和股票代码。每篇纳入分析的帖子按五档规则标注 **-2 至 +2 市场态度分**、范围/时间尺度及星主观点依据；排除的原始提问也在排除清单标 `0（无星主实质回应）`，确保 raw 每篇都有分。能量评分及其他用户评论不能代替星主判断。
5. **仅分析阶段筛选**：非星主的提问，若无求学/大牛的实质回答或实质评论，排除在正文浓缩之外；raw 原样保留。其他帖子无评分也要总结，不按 Top N 筛选。覆盖审计写明 raw 总数、分析篇数、排除篇数及排除的 ID/原因，验证 `raw = 分析 + 排除`、无重复遗漏。分类与格式遵循下方分析章节。
6. **分析 MD 写完后必须回填同一路径 raw HTML**：执行 `python3 /Users/melo/src-skills/src-zsxq/zsxq-quant/duoyu/overlay_scores.py "/Users/melo/doc-Dgf/duoyu/{MMDD}-多鱼朋友圈_raw_{start}_{end}.html" "/Users/melo/doc-Dgf/duoyu/{MMDD}-多鱼朋友圈_{start}_{end}.md"`。脚本按唯一 ID 严格对齐每张卡片（含排除帖），要求全部卡片各有一条有效市场态度，拒绝多余/重复/畸形评分；失败不覆盖原 HTML，成功原子替换并可重复运行。重新导出会清除旧标注，每次新分析完成后须重跑回填。
   回填脚本使用仓库根目录 `__common/stance.py` 共用人工态度字段校验和转义组件；仍从多鱼 Markdown 人工评分读取，按 raw 卡片 ID 原位更新 HTML，不创建独立的大锅饭式分析页，也不自动评估帖子情绪。
7. 回填成功后再报告 raw 与分析文件路径、日期范围、逐日及分页数量、OCR 图片数、分析数、排除数与守恒关系，及市场态度各档篇数（总和等于 raw 总数）、HTML 卡片评分数。认证、分页、图片下载、OCR、分析覆盖或回填失败时停止，不以旧 raw 冒充本次成功导出；若分析无法确认星主是否回应，保守保留并注明不确定，不能虚构。

### 4. 数量定义与验证

必须区分以下数量：

- `API 分页返回数`：各成功分页响应中 `topics` 数组长度之和，包含范围外条目和分页重复条目。
- `日期范围外数量`：API 为确定边界而返回、但不在请求闭区间内的条目数。
- `分页重复数`：因 `end_time` 边界重叠而出现、按 `topic_id` 去重的条目数。
- `日期范围内总数`：闭区间内按 `topic_id` 去重后的帖子数。
- `评分过滤数`：仅在显式传入 `--min-score` 时被删除的非 `q&a` 帖子数。
- `输出总数`：最终 HTML 中 `.post-card` 的非 `q&a` 帖子数与用户提问数之和。

必须验证两条数量守恒关系：

```text
API 分页返回数
= 日期范围外数量 + 分页重复数 + 日期范围内总数

日期范围内总数
= 输出总数 + 评分过滤数
```

同时验证逐日数量之和等于日期范围内总数。任一等式不成立时停止，不写最终文件。

## 错误处理

- 凭据文件不可安全读取、编码无效或权限不符合要求：输出不含凭据内容的明确错误并停止。
- 认证失败：提示更新套件根目录 `.env` 中的 `ZSXQ_ACCESS_TOKEN`，不要回显旧 token。
- API 限流（如 code 1059）：等待后重试；持续失败则明确说明未完成，不得把部分结果报告为完整导出。
- 网络错误：最多重试 3 次；仍失败则停止，不生成新的最终文件。
- 时间字段无效：报告 `topic_id` 并停止，不能静默跳过帖子。
- 日期范围内的帖子缺少 `topic_id`：停止，不能以无法可靠去重的数据继续导出。
- API 响应包络或帖子字段结构异常：最多重试 3 次；仍异常则输出明确失败摘要，不得抛出未处理 traceback 或覆盖旧输出。
- API 重定向：拒绝跟随并停止，防止 access token Cookie 被转发。
- 非终止空页或 API 时间顺序异常：停止，不能把可能的部分结果当作完整导出。
- 分页游标不前进：停止并报告前后游标值，防止重复请求或死循环。
- 数量不守恒：停止并报告各阶段计数，不得写入最终文件。
- 写入失败：删除临时文件，保留明确错误摘要。

## 覆盖与筛选

先记录顶部抓取审计及每张卡片的 `data-post-id`、作者、时间、正文、问答、OCR 和评论。默认 raw 包含**全部**原始帖子，包括问题和未回答帖。按以下互斥规则分配：

- **排除（仅分析正文）**：非星主发起、内容主要是提问，且求学和大牛均没有实质回答或评论。星主仅“收到”、表情、赞同等无具体判断/信息的回复不算实质；其他用户的回答也不替代星主回答。例如“还能继续拿吗？”在没有求学/大牛实质回复时排除。若作者/回复归属不清或是否提问不确定，保守保留并注明待核实。
- **星主发言**：求学、大牛发布的帖子（含图片独占帖），以及其他有实质内容的非提问帖，逐篇摘要。
- **用户问答**：有求学/大牛实质回答或评论的用户问题，摘要必须包括问题与星主回应要点；如评论仅在 API 的评论预览里，明确说明是评论预览，不冒充完整讨论。

不要使用大锅饭的“星大派/直播总结”、评分排序或 Top N 规则；无评分也保留。按发布时间降序呈现，摘要尽量 1–3 句，保留原文关键数据、标的与风险，避免复述空话、免责声明或无信息量评论。帖子标题可简写但不得改变含义。每条含帖子 ID 以便精确核对。

## 市场态度量化（试行）

对**每篇纳入分析的帖子**，仅依据求学/大牛的正文、可辨认的图片 OCR（对照原图）及其明确归属的回答或评论，标注 `-2` 到 `+2` 的市场态度分、判断范围（整体市场/板块/标的）、时间尺度和一句原文依据。不得把提问者、普通用户评论或新闻快讯本身当作星主观点；也不得将帖子“无能量评分”误作态度 0 分。

- `-2`：明确看跌、要求离场或避险；`-1`：偏谨慎、认为反弹难持续或不建议追高/加仓；`0`：双向情景、观望、纯交易纪律/事实陈述或没有可归属方向判断（必须写“方向信息不足”）；`+1`：条件性看好修复或温和上涨；`+2`：明确看好持续上行并建议增加风险敞口。
- 若一帖有多个方向，仅对星主实际谈论的范围评分；需同时陈述的不同范围，选帖子主问题的范围，其他范围写进理由。若星主后续回答修正正文判断，采用最新明确判断并注明时间。短期看好、长期谨慎可记 `0` 并写两个时间尺度，不能硬判单向。仅止损规则（如“跌 5% 走”）不等于看空。
- 在每条摘要后统一写 `**市场态度：+1｜光模块｜短期** — 依据：求学认为……`；没有明确方向写 `**市场态度：0｜标的｜未指定** — 依据：星主仅解释形态，方向信息不足。` **排除清单中的原始帖子也保留一行 `0（无星主实质回应）`**，不因此纳入浓缩正文。顶部列五档图例，说明此分只归类观点而非投资建议、预测收益或原帖能量评分；统计各档数量，总和必须等于 raw 总篇数。OCR 不确定时保守记 0 并解释。
