# 知识星球完整工作流

一键执行「抓取 → 分析」两步流程，输出原始数据文件和浓缩总结文件。**全程通过 zsxq API 抓取，不需要任何浏览器操作。**

## 输入参数

`$ARGUMENTS` 格式：`[日期过滤]`（见下方导出章节）

| 格式 | 示例 | 含义 |
|------|------|------|
| 单日 | `2026-05-05` | 只导出该日帖子 |
| 日期范围 | `2026-05-01:2026-05-05` | 导出从起始日到结束日的帖子 |
| 相对天数 | `1d` / `3d` / `7d` | 导出最近 N 天的帖子 |
| 无参数 | 留空 | 默认导出最近 3 天 |

## 执行步骤

### 第一步：抓取原始数据

按照下方“知识星球内容导出”章节的完整流程执行：

1. `date +%Y-%m-%d` 获取今天日期，解析日期参数得到 start_date / end_date
2. **删除同日期范围的旧 raw 文件**（每次必须重新拉取，不使用缓存）
3. 执行导出脚本（token 自动从 `.env` 读取）：
   ```bash
   python3 /Users/melo/doc-Dgf/zsxq_export.py --days <N>
   # 或指定范围
   python3 /Users/melo/doc-Dgf/zsxq_export.py --start <start_date> --end <end_date>
   ```
4. 脚本内置规则：
   - 按日期范围过滤
   - **完整保留其他用户提问（`q&a` 类型）帖子，并写入文末独立的「🙋 用户提问」章节**
   - 每篇星主帖子和用户提问标题末尾都写入原始 `ID \`{topic_id}\``
   - **不做评分阈值过滤，保留所有星主帖子**（评分仅用于展示；用户提问不参与评分过滤）
   - 翻页连续重试失败时停止导出，不生成不完整 raw 文件
5. 输出到 `/Users/melo/doc-Dgf/zsxq_md/{MMDD}_大锅饭_raw_{start_date}_{end_date}.md`
6. 验证输出（星主帖子数量、用户提问数量、独立章节、标题末尾唯一 topic ID 及正文完整性）

**此步骤必须完整执行完毕后，再进入第二步。**

### 第二步：浓缩总结

读取第一步生成的 raw 文件，按照下方“知识星球内容分析”章节的完整流程执行：

1. 读取 raw 文件并解析全部帖子
2. 按互斥优先级分类：
   - **用户提问专栏**：raw 文件「🙋 用户提问」章节下的全部 `q&a` 帖子
   - **星大派专栏**：其余帖子中，正文/标题以「星大派」开头的帖子，以及**标题中含「直播总结」的帖子**
   - **星主普通专栏**：剩余所有星主帖子，包括无评分帖子
3. 对三个专栏中的**全部帖子**逐篇浓缩总结，不执行 Top 10 筛选，不因无评分而丢弃
4. 排序：三个专栏内部统一按发帖时间降序排列；能量评分只展示，不参与排序
5. 验证 `星大派数量 + 星主普通数量 + 用户提问数量 = raw 总数`，并检查无重复、无遗漏
6. 输出自包含 HTML 到 `/Users/melo/doc-Dgf/zsxq_md/{MMDD}_大锅饭_{start_date}_{end_date}.html`；三个专栏分区展示，每篇消息下方提供独立的“查看原文”折叠入口，默认收起，不提供页面顶部全局原文开关
7. 人工复核每篇五档市场态度及依据，按下方分析章节的 JSON 字段写出审阅记录，先生成独立草稿 HTML，再执行 `python3 /Users/melo/src-skills/src-zsxq/zsxq-quant/dgf/apply_stances.py RAW.md DRAFT.html REVIEWED.json OUTPUT.html`；必须覆盖全部 raw 帖子（含未回答提问），成功后才将目标 HTML 视为分析完成。程序不替代人工浓缩、评论归属检查或事实核对。

### 最终输出

告知用户：
- raw 文件路径
- 分析文件路径
- 星大派专栏帖子数量
- 星主普通专栏帖子数量（有评分/无评分）
- 用户提问专栏帖子数量（已回答/未回答）
- raw 总数及三类全量覆盖校验结果
- 日期范围

- 两步必须顺序执行，第一步完成后再做第二步
- 如果第一步失败（如 token 过期返回 HTTP 401、限流 code 1059），**不执行第二步**，直接提示用户：
  - token 过期：提示更新 `/Users/melo/src-skills/src-zsxq/zsxq-quant/dgf/.env`（浏览器 Cookie 中重新获取 `zsxq_access_token`）

- **export 阶段不按评分过滤星主帖子**；用户提问也完整保留到 raw 文件文末独立章节
- analyse 阶段必须总结全部 raw 帖子：星大派、星主普通、用户提问三类互斥且合计等于 raw 总数
- 能量评分只作为展示信息，不再用于排序、Top 10 筛选或删除帖子

- 分析前读取套件根目录 `blackwords`，首次出现黑话时解释；每篇分析卡片依据星主发布的正文和回复标注市场态度 `-2` 至 `+2`（方向信息不足记 `0` 并说明，与能量分不同），注明判断范围与一句依据；研报转述需标明来源，不能冒充星主个人推荐。卡片、评论、原文区背景要有层次。
- 导出及分析细节均在本文件对应章节，单独调用导出脚本不自动分析。

## 执行步骤

### 1. 完整读取并解析 raw 文件

解析以下内容：

- 星主帖子：标题通常为 `## ⭐ {评分或无}分 | {MM-DD HH:MM} | {标题}`
- 用户提问章节：以 `## 🙋 用户提问` 开始，每篇标题通常为 `### ❓ ⭐ {评分或无}分 | {MM-DD HH:MM} | {标题}`
- 每篇帖子的发布时间、能量评分、正文、标签、附件和评论；嵌套评论以 `作者 回复 对象：内容` 保留 API `repliee.name` 的真实对象，不得把“暂时没有”等回答错归给相邻用户。
- 用户提问中的提问者、问题正文、回答者及回答正文
- 每篇帖子的完整原始 Markdown 片段，作为 HTML 中可选显示的 raw 原文

为每篇帖子生成稳定且唯一的 `post_id`：**新导出的 raw** 每篇标题（星主及 `q&a`）末尾均带 `| ID `原始topic_id``，卡片 `data-post-id` 必须直接使用这个 ID，不得自行编造映射；只有旧版 raw 无任何原始 ID 时才沿用“类型 + 发布时间 + 标题”的稳定组合。新旧格式不许在同一份 raw 中混用。

### 2. 按优先级分类

严格按以下优先级分类，保证互斥且完整：

1. **用户提问专栏**
   - raw 中 `## 🙋 用户提问` 章节下的所有 `### ❓` 帖子
   - 即使回答正文以“星大派”开头，仍归为用户提问
2. **星大派专栏**
   - 在非 `q&a` 星主帖子中，满足以下任一条件：
     1. 标题或正文去除评分前缀、Markdown 加粗符号和空白后，以“星大派”开头
     2. 标题中包含“直播总结”，不要求以该词开头，不受评分影响
3. **星主普通专栏**
   - 其余所有非 `q&a` 星主帖子
   - 无评分帖子也必须保留

分类完成后执行覆盖校验：

- 统计 raw 总数 `J`
- 统计星大派 `M`、星主普通 `N`、用户提问 `Q`
- 验证 `M + N + Q = J`
- 根据 `post_id` 检查无重复、无遗漏
- 若不相等，重新解析并定位问题，不得静默生成不完整 HTML

### 3. 浓缩总结全部帖子

对三个专栏中的**每一篇帖子**进行浓缩，不设置 Top N，不按评分淘汰。

#### 通用总结原则

- 每篇用 **2-5 句话**概括核心观点、关键数据和结论
- 内容较长时按逻辑分成 1-3 个短段落
- 保留并用粗体标记关键数字、增速、价格、目标价、评级和核心结论
- 公司名称和股票代码必须完整保留并加粗，如 **协创数据**（**300857.SZ**）
- 不额外搜索公司主营业务，不添加原文没有的事实
- 删除免责声明、重复格式文本和无信息量内容
- 评论区仅保留有信息价值的补充、澄清或重要追问；**`三线文案大锅饭`（星主）的评论和回答必须全部保留并纳入总结要点，不得因"仅保留有价值评论"而省略**
- 每篇卡片在浓缩摘要后增加独立的评论区，展示该帖 raw 中**全部评论原文**，保留评论顺序、作者及明确的回复对象；重点作者仅用黄色文字标注署名（深色模式用亮黄），不使用菱形、金色背景、边框或徽标。用户提问中的其回答同样仅突出署名。
- 原文若截断或缺失，必须明确标注，不得臆测补全

#### 黑话与市场态度评分

- 分析前读取 `/Users/melo/src-skills/src-zsxq/zsxq-quant/dgf/blackwords`（每行 `词 - 解释`）；例如“十六字”在总结中首次出现时括注其交易策略，“柚子”按“游资”解释。只解释词义，不替换或改写折叠区原文；如词义与上下文冲突，以原帖为准。
- **市场态度分**与原帖能量评分完全独立；每篇卡片都展示 `-2 / -1 / 0 / +1 / +2`，写明判断范围、时间尺度及一句可追溯依据。评分归类星主发布的正文及其回复所表达的方向；研报转述只能标记为“帖文引用观点”，不能冒充星主个人推荐。无方向判断时给 `0（信息不足）`，不冒充“多空相抵”。
- 简单规则：明确判断整体或板块将明显下跌、要求避险/减仓 → `-2`；偏谨慎、反弹持续性存疑或建议降低仓位 → `-1`；多空相抵、震荡观望或信息不足 → `0`（理由区分）；看好修复但提示风险 → `+1`；明确趋势上行并建议增加风险敞口 → `+2`。同帖冲突时以后发布的星主回复为准；观点只指向单个标的时注明标的范围，不上升为整个市场。
- 评分只归类帖文方向，不是收益预测；页面头部提供五档图例和 `0（信息不足）` 释义，每篇标明依据（正文、研报转述或“回复某某”），对照本次 raw 的每一篇。

#### 用户提问总结规则

每篇用户提问必须同时覆盖：

- **问题要点**：提问者关心的标的、现象或决策问题
- **回答要点**：星主回答的判断、逻辑、条件和风险提示
- 若尚无回答，写明“截至导出时暂无回答”
- 若回答中包含评分，保留评分，但评分不参与筛选和排序

#### 不同内容类型的重点

| 类型 | 总结重点 |
|------|----------|
| 星大派每日热点 | 当日核心事件、关键数据、受益方向与风险 |
| 星大派锐评/特刊 | 核心观点、操作纪律、政策或行业逻辑 |
| 直播总结 | 直播核心观点、操作框架、重点标的与风险提示 |
| 研报精读 | 核心观点、关键数据、评级/目标价、利好公司 |
| 行业分析 | 核心判断、逻辑链、重点关注方向 |
| 普通观点 | 主要结论、操作框架、风险提示 |
| 用户提问 | 问题要点 + 回答要点 + 有价值的追问或补充 |

### 4. 专栏分隔与内部排序

- 三个大类必须使用三个独立 `<section>`，拥有清晰的标题、数量和视觉边界，不得把不同类别的卡片混排
- 专栏整体顺序固定为：星大派专栏 → 星主普通专栏 → 用户提问专栏
- **三个专栏内部全部只按发布时间降序排列（最新在前）**

- 无法解析发布时间的帖子放在所属专栏末尾，并在生成结果中标记“时间未知”，不得丢弃

### 5. 生成自包含 HTML

输出路径为 raw 文件名去除 `_raw_` 并将扩展名改为 `.html`：

- raw：`/Users/melo/doc-Dgf/zsxq_md/{MMDD}_大锅饭_raw_{start_date}_{end_date}.md`
- 分析：`/Users/melo/doc-Dgf/zsxq_md/{MMDD}_大锅饭_{start_date}_{end_date}.html`

HTML 必须：

- 使用 UTF-8，包含 `<!doctype html>` 和响应式 viewport
- CSS、JavaScript 全部内嵌，不依赖 CDN、外部字体或网络请求，可离线打开
- 配色参考多鱼朋友圈 raw HTML：页面底色 `#f4f1ea`、内容面板 `#fffdf8`、正文 `#25221d`、边框 `#d9d1c3`；同时提供 `prefers-color-scheme: dark` 的深色变量组。文章卡片、总结区、评论区、原文区背景要有层次，但重点作者评论本身不铺底色。
- `三线文案大锅饭` 的署名使用黄色字体（浅色模式深金 `#926300`，深色模式亮黄 `#ffd67a`），不加菱形图标、整行背景或左边框。
- 在卡片的总结下显示独立的市场态度评分行及其依据、判断范围；不得将其误写为原帖能量评分。
- 默认显示浓缩总结；每篇 raw 原文入口默认折叠
- 不提供页面顶部或其他全局“显示原文 / 隐藏原文”按钮
- 每篇帖子的 raw 原文使用 `<details class="raw-block"><summary>查看原文</summary>...</details>`，支持逐篇独立展开/收起
- `<details>` 初始不得包含 `open` 属性，保证页面载入时原文默认折叠
- raw 原文必须 HTML 转义后写入，至少转义 `& < > " '`，不得把 raw 中的 HTML 或脚本直接执行
- raw 原文使用 `white-space: pre-wrap` 保留换行，正文过长时允许区块内部滚动
- 每篇帖子使用独立 `.post-card`，包含发布时间、标题、可选评分、浓缩总结和对应 raw 原文
- 页面提供三个专栏的页内导航锚点和顶部数量汇总
- 即使某类数量为 0，也保留对应 `<section>` 并显示“本期无此类帖子”


`OUTPUT.html` 仍按第 5 步原有文件名；`DRAFT.html` 使用不同路径。程序检查 JSON 五档/字段/唯一 ID、与全部卡片精确覆盖、raw 帖子数及原文标题对齐；新 raw 另校验每张卡片 ID 与 raw topic ID 一致，旧 raw 无 ID 时只能核对帖子数、逐帖原文标题和卡片唯一 ID，无法追溯 API topic ID。三个专栏和逐篇摘要/折叠区也受检查。失败不替换目标文件，成功原子写入。人工审核摘要、评论归属、原文完整性和评分依据仍是必须的；此工具不是 raw Markdown 渲染器。视觉保留本 HTML 的卡片层级、间距、浅深色变量（包括 `--summary`/`--gold`），不照搬多鱼 raw 页面布局。
