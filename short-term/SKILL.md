# 短线情绪、持仓计划与冻结复盘（多鱼 + 大锅饭 + 布鲁斯）

**每次调用始终输出三部分**：①多鱼/大锅饭/布鲁斯分析；②最新预测或明确标注的历史盘中留档；③反馈及待结算状态。正式预测通常在已完成收盘 15:05 后至下一开市日 09:30 前冻结。交易日 09:30–15:05 也可**延迟出具**，但只能使用开盘前已保存且未改动的两份 final HTML 和板块快照，不使用盘中行情、帖子或事后标注；文件创建与修改时间均须早于当天 09:30，帖子时间严格早于 09:30。实际出具时间记录为盘中时间、`source_cutoff=09:30`、`provenance=late_preopen_snapshot`；首个目标是下一完整交易日，不能将已开盘的当天计为目标。无合格快照则不生成。延迟样本的基准是上一完整收盘，反馈至第二目标日的收益包含出具当日行情，必须单列，不能与常规两日样本合并。既有 `intraday_archived_unfrozen` 草案仍独立处理。布鲁斯（BruceGold 抖音字幕汇总）为**可选第三源**：存在时纳入三源视角、缺失不阻塞。

## 输入参数

`$ARGUMENTS`：`/short-term [YYYY-MM-DD|MMDD] [N|--window-days N]`，N 为 1–5（默认 3）；省略日期以当天 `date +%m%d` 定位 HTML。显式日期只选分析期次，绝不用于历史补冻。正常出具使用当日五日 final HTML；盘中延迟出具可使用开盘前保存的当日或前一自然日五日 final HTML，双源同一期且未改动。**目标日 09:30 开盘前可对同一目标重新预测并覆盖昨晚版本**：重新分析早间新帖和持仓，验证后写入新预测并移除旧文件，目录内只留一份该目标的正式预测；真实出具时间、输入哈希随新文件更新。已生成反馈的预测不得覆盖。09:30 起当天目标不可再改；交易日盘中只能出具下一完整交易日预测，且盘中已出具的下一交易日预测不得在当日收盘后覆盖。

### 第一步：定位同一期五天分析 HTML（任意时段只读分析）

```bash

ls /Users/melo/doc-Dgf/zsxq_md/{MMDD}_大锅饭_2*.html
# 布鲁斯按期次末日选不晚于该日的最新文件，不要求与双源同名日期：
python3 - <YYYY-MM-DD> <<'PY'
from datetime import date
from pathlib import Path
import sys
end = date.fromisoformat(sys.argv[1])
root = Path('/Users/melo/doc-Dgf/bruceGold')
matches = []
for path in root.glob('[0-9][0-9][0-9][0-9]_BruceGold_字幕汇总.html'):
    stamp = path.name[:4]
    try:
        issue = date.fromtimestamp(path.stat().st_mtime).replace(month=int(stamp[:2]), day=int(stamp[2:]))
```

- 双源之一缺失时第一部分注明缺源，提示运行对应 pipeline；不单源降级，也不生成预测，但仍读取既有档案。前一日双源如存在且均满足盘前证明，可用于盘中延迟出具，不要因当天文件缺失而误判没有输入。

### 第四步：滚动自然日市场情绪与成交额


五个自然日 D1–D5 按所选 N（1–5，默认 3）生成 `5-N+1` 个连续 N 日窗口，每个窗口以末日的**下一个自然日**为目标日，不顺延至下一个交易日。仅纳入窗口首日 00:00 至目标日 **09:30 前**的帖子（09:30 恰好发布不纳入）；五日 final HTML 不含目标日早盘帖子时不得额外抓取补齐。目标日非交易日也列方向，不反馈价格。

每源保留 -2/-1/0/+1/+2 五档分布、篇数及全帖均分，同时按 `scope` 与 `timescale` 区分大盘整体且适用于未来两个交易日的观点和板块/个股、海外市场或其他期限的观点。合并大盘方向只使用前者，先算每源均分再各源等权，不让发帖量多的一源占主导；一源缺合格观点或样本很少/方向接近零时明确提示信号薄弱。布鲁斯帖子来源为 AI 字幕识别且未经人工复核，其评分标注"AI分析未经人工复核"，作为独立博主观点参与合并，引用时须注明该来源属性。**当前计划**的沪深 A 股成交额来自 `/Users/melo/src-skills/dailyTradeSum/me1o-tushare/scripts/fetch_daily_trade_sum.py` 的 Tushare `daily` 接口，单位 **亿元**，不含 ETF、债券、北交所。脚本只查询上一完整交易日，注明所属日期；缺失写不可用、不补零。这个当前快照**不是历史滚动窗口当时可见量能**，不得拿它回填以前目标日或虚构历史放量。目标日成交额只能在收盘后作复盘背景，不参与该日预测。

**回看偏差**：final HTML 的评分和解读事后形成，发帖时间过滤无法消除未来信息；滚动表只是回溯性方向代理，不是严格历史回测，也不报告胜率。对持仓的预测须在决策时刻冻结，不能根据后来数据重建历史预测。

### 第六步：逐只决策并冻结两交易日计划

对每只持仓检索代码、公司名、行业关键词与各源明确点名的观点，结合全市场评分分布、最近三个**已收盘**交易日的价格及最新完整沪深 A 股成交额。必须三选一：**增持**需明确点名 +1/+2 且证据具体；**减持**需明确点名 -1/-2（或整体极端偏空且各源证据可迁移至该股）；其他情况**保持不动**。保持不动也是须反馈的仓位决策，即使起因是证据不足，也不是横盘预测或免评；若明确预测价格平稳，可附 `"hold_intent": "sideways"` 记录意图，但 v3 仍按保持仓位相对调整仓位的机会成本评价。注明帖子发布时间、分数、出处、相反观点与量能背景；布鲁斯证据须标注"字幕/未经人工复核"；不要把网络/券商转述算成星主建议。整体情绪和板块/个股信号分别标明。

若要把板块帖应用于持仓，先捕获**当时** efinance/Eastmoney 的股票板块归属，失败就标记关联不可核实，不按股票名称或模糊印象猜板块：

```bash
.venv/bin/python board_snapshot.py --output <临时板块快照.json>
```

仅把板块数据用作**关联核验**，不自动生成买卖动作。`scope` 必须是该帖态度行中原样出现的板块词；逐股引用 `source` (`duoyu`/`dgf`/`brucegold`)、`post_id`、股票真实的 `board_code` 和具体理由。代码将完全同名标 `exact`、包含关系标 `related`，否则标 `unverified`；**related 和 unverified 都不是帖文直接点名该股**。例如“光通信”与长飞的“光通信模块”为 related；“大储能”与宁德的“储能概念”为 unverified，不得把后者说成“大储能”精确匹配或直接买入信号。宽泛概念/多业务归属需要人工核对业务敞口及反向证据；若获取板块失败，不可凭旧查询结果补写该期。

收盘 **15:05 后至下一确认交易日 09:30 前**可出具下一交易日计划；盘前同一目标如已有昨晚版本，必须重新评估当日新帖与量能，完成新的判断后可**覆盖原预测**，只保留一份；资料或行情获取失败时旧预测仍保留。**09:30 起当天预测锁定，绝不回填盘中信息。**交易日 **09:30–15:05** 可基于两份开盘前已保存的 final HTML（及盘前布鲁斯文件，如有）**延迟出具下一交易日计划**；校验源文件及引用板块快照的创建/修改时间均不晚于 09:30，原帖均严格早于 09:30，且五日范围末日为当天或前一自然日。盘中最新源文件、盘中价格、盘中新生成的板块快照和事后标注不得输入该模式。目标交易日由 Tushare `trade_cal` 交易日历确认，结果本地缓存于 `trade_cal_cache.json`（一次拉取覆盖未来 45 天，之后不再调用，规避 5 次/天限频）；日历 API 不可用时可用 `freeze --target-date YYYY-MM-DD` 由人工确认目标日绕过，但上一完整收盘行情缺失仍停止。若盘前 final HTML 在 09:30 后被**内容不变的良性重渲染**（如本地调试 pipeline）改动了文件时间戳，可在已核实"全部帖子严格早于 09:30"后用 `freeze --trust-preopen-source` 跳过文件 mtime 闸门——帖子时间内容检查仍强制执行，且覆盖会写入预测记录 `preopen_source_mtime_trusted` 留痕；不得用于真正纳入了盘中帖子或事后改分的文件。实际出具时间不得倒填。收盘后常规出具仍要求多鱼/大锅饭范围末日为当天，帖文不晚于出具时刻。

### 第七步：已完成计划复盘与反馈

预测反馈只在**目标交易日收盘 15:05 后**生成；目标日已过去时，即使当前时间早于 15:05，也可结算已完成的历史收盘。先确定**上一已完成交易日**（收盘 15:05 前为前一交易日，15:05 后为当日；休市日为最近已完成交易日），以预测记录中的 `first_target_session` 匹配，不以文件名前缀或报告期次匹配。第③部分只展示这个交易日为**首目标交易日**的正式预测反馈；若不存在，明确写「缺乏 {上一已完成交易日} 预测，无法执行预测反馈」，不得拿更早预测、第二目标交易日结算或盘中历史草案充数。`review-pending` 仍尝试结算全部预测文件以维护档案，不因展示范围收窄而停掉旧预测的完整两日结算；但终端报告/HTML 只列上述目标的反馈。常规预测在首目标日收盘后即可部分结算（`return_window=partial_one_of_two_sessions`），第二交易日收盘后自动更新为完整两日反馈（旧部分反馈被替换）；历史盘中留档 `1115_2026-11-16_1355_prediction.md` 特例仅需 11-16 完整收盘。反馈独立新建 Markdown，含原文件 SHA-256；完整两日反馈生成后预测不得再覆盖；部分反馈可被更多数据替换。未复权价格受分红、拆股扰动时需人工核对。
帖子归因与动作评分**分开**：反馈按每个持仓在冻结时保存的 `post_refs`，逐条列“多鱼/大锅饭/布鲁斯·发帖时间·ID·当时分数·范围·期限”，将帖子正负方向与该持仓评价区间的涨跌比较；超过 ±0.5% 为“方向相符/相悖”，中性带为“价格落在中性带”，0 分为“无方向评分”。这只描述帖文方向与价格同向性，**不是**帖文对该股的因果命中率，尤其大盘帖、板块帖、长周期帖不可作个股两日预测准确率。相同帖子映射多股是相关样本，不独立累加；只有积累多个点时冻结样本后，才考虑人工审视评分 rubric，不能自动重打历史帖。旧预测无 `post_refs` 时仅可使用**原预测内已冻结的** `board_evidence` 帖子态度，标为“仅板块引用、部分归因”；其他没有点时结构化证据的引用写“无法归因”，保留旧评分，不从后来的 HTML/自由文本臆补。
冻结时除逐股 `post_refs` 外，还按来源保存当期五日 HTML 在输入截止前的**全帖均分/篇数**与严格满足“大盘整体＋未来两个交易日”的**可比大盘均分/篇数及帖子快照**，写入 `market_context`；不能用事后 HTML 补写旧预测。全帖均分混合板块/个股/海外及不同期限，只是情绪背景；可比大盘信号可影响所有持仓的风险敞口判断，不要求点名个股，但与个股价格的对照只是市场背景对照，不是个股预测命中或独立样本。某来源无可比帖时明确写“来源缺口”，不得用全帖均分替代。动作评分按预测内冻结版本结算：v3 原定义保留；v4 统一提高所有 `hold` 的最重扣分阈值至绝对涨跌超过 4%，不因大盘情绪、缺少个股/板块帖而逐股豁免。报告中把 `missed_add` 写成「未增加额外仓位的机会成本（原持仓仍享受上涨）」、`missed_reduce` 写成「未减仓避开回撤」、`no_change_reasonable` 写成「维持仓位避免无效调仓」；只改展示措辞，不改变存档枚举。帖子引用缺失仅表示无法做**具体帖子**归因，不表示没有博主观点相悖；既有档案若无冻结 `market_context`，仍不得回填。

## 注意

- 两份 final HTML 和持仓只读；预测仅能在同目标开盘前且未生成完整两日反馈时覆盖；部分反馈（仅首日收盘）可被 `review-pending` 自动替换为完整两日反馈。覆盖会丢失昨晚判断的审计历史；只保留新档是本流程明确取舍。
